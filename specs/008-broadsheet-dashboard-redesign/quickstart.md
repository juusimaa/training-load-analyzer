# Quickstart: Validating the Broadsheet Dashboard Redesign

**Feature**: 008-broadsheet-dashboard-redesign | **Date**: 2026-09-19

How to run the feature and prove it satisfies the spec. Implementation detail belongs in `tasks.md`;
this is the validation guide.

## Prerequisites

- .NET SDK per `global.json`
- The Strava client secret in user secrets (already configured for the Web project; the dashboard
  renders stored history without it, so most validation below needs no Strava access)
- `docs/ui/index.html` open in a browser as the visual reference to compare against

## Running

```bash
dotnet build TrainingLoadAnalyzer.sln
dotnet run --project src/TrainingLoadAnalyzer.Web    # http://localhost:5062
```

```bash
dotnet test                                                        # everything
dotnet test tests/TrainingLoadAnalyzer.Web.Tests                   # the UI + theme suites
dotnet test tests/TrainingLoadAnalyzer.Web.Tests --filter FullyQualifiedName~Theme
```

## The order the suite should go green in

Each step has a RED state before its implementation exists. Matching tasks are generated by
`/speckit-tasks`; this is the shape they must follow.

| # | Validates | Goes green when |
| --- | --- | --- |
| 1 | Token set exists in both schemes | `PaletteSlotTests`, repointed at the parsed custom properties of `wwwroot/Theme/broadsheet.css`, finds every token in [data-model.md §2](./data-model.md) under `:root` **and** under the dark media query |
| 2 | Contrast (FR-015, SC-005) | `PaletteContrastTests` passes every pairing in the contrast table, in both schemes, with the load-bar exemption named explicitly |
| 3 | Colour discipline (SC-009) | `ColourDisciplineTests` passes **unmodified** — it will fail loudly if the vendored sheet lands outside a `Theme` path segment, or if a chart stroke is written as an SVG presentation attribute |
| 4 | Chart geometry | The revived `MetricsChartTests` pass, including the invariant-culture coordinate cases, plus new cases for load bars, the zero rule and axis ticks |
| 5 | Information preservation (FR-002, SC-001) | `InformationPreservationTests` passes **with its assertions unchanged**. This is the safety net — see the warning below |
| 6 | Regions, hooks and states | `DashboardComponentTests` passes with the hooks in [contracts §3](./contracts/dashboard-ui.md) intact and `AddMudServices()` gone |
| 7 | Host still serves | `StartupTests` still renders stored figures over real HTTP with Strava unreachable |

> **The step-5 rule.** `InformationPreservationTests` asserts on text extracted from stripped
> markup precisely so a redesign cannot quietly drop a qualifier. If one of its assertions fails,
> the redesign has lost something an athlete relied on — fix the markup, not the assertion.
> SC-002 permits rewriting only assertions bound to markup this feature deliberately replaces, and
> forbids weakening, vacating or silently removing any.

## Manual validation

Run with the fixture history (`AsOf = 2026-09-18`) so figures are comparable to the reference.

**Layout and figures (US1)**

1. Every control — as-of date, window, Strava state, sync button, max heart rate — is in the rail
   and nowhere else.
2. Fitness, Fatigue, Form and week load sit as four peers in one row; Fitness reads cyan, Fatigue
   magenta, the other two in ink.
3. Switch the window to 30, then 90, then 180: the plot, the heading and the date axis all follow,
   with no full page reload.
4. Bars sit behind the three lines; the Form line is dashed and crosses a visible zero rule.
5. Recent sessions show seven rows, basis as a tag reading "measured" or "estimated".

**Information preservation (US2)** — the highest-value manual pass. `git stash` the change, load
the same history, screenshot the dashboard; restore and compare. Every figure, qualifier, message,
timestamp and link must still be present and worded identically.

**States (US3)** — walk each row of the [state contract](./contracts/dashboard-ui.md#2-state-contract):
empty database with and without a connected account, an unreadable store, a revoked credential, a
rate-limited sync, and the first paint while history loads. Each must look like the same design,
not like the previous card style.

**Responsive (US4)** — 320px, 768px, 1440px, 2560px, and 200% browser zoom: no horizontal scroll,
nothing clipped or overlapping, rail stacks below 60rem, chart scales.

**Accessibility (US5)** — tab through the page and confirm a visible focus ring on the window
options, the sync button and every link; toggle the OS appearance with the page open and confirm it
follows without a reload and without content changing; view in greyscale and confirm every
distinction outside the plot survives.

## What only human review can settle

State these explicitly in the completion review rather than implying a test covered them:

- Whether the page **reads as newsprint** — the point of the feature, and not assertable.
- `ReconnectModal.razor` **has no test coverage at all** and is the heaviest consumer of the old
  palette tokens (7 references). Its restyling is unverified by the suite; open it and check it in
  both schemes.
- Dark-scheme legibility of the three chart series against the dark ground. The ratios are tested;
  whether the dashed Form line still reads at a glance is not.
- That whitespace and hairline rules separate regions as convincingly in dark as in light — the
  vendored tokens' own comment notes elevation works differently there.
- **SC-008**: show the dashboard to someone who has not seen it and confirm they can name their
  Fitness, Fatigue and Form figures within 5 seconds. A display-size figure row should make this
  easy; if it does not, the hierarchy is wrong.

## Measuring NFR-001

The claim that the redesign renders no slower is an argument until measured. Load `/` with the same
fixture history on the pre-redesign commit and on the redesigned build, with the browser's network
panel recording, and note the time to the first rendered figure in each. Record both numbers in the
completion review rather than asserting the improvement.

## Compliance sweep

`scripts/compliance-006.sh` is the precedent: grep-able checks that a test cannot express. A
`compliance-008.sh` should assert that `MudBlazor` appears nowhere in `src/` or `tests/` (no
`PackageReference`, no `@using`, no `AddMudServices`, no `mud-` class, no `MudChartBounds`), that no
`.razor` file carries an SVG `stroke=`/`fill=` colour literal, and that `app.css` no longer carries
the dead `.mud-button-root` rules.

## Constitution compliance review

Per the constitution's Development Workflow, the completion review must explicitly check Principle I
(was this built test-first), Principle II (no Strava leak — this feature should touch neither the
domain nor Infrastructure at all) and Principle III (did the vendored subset stay a subset, and did
any speculative abstraction creep in). Record the outcome, including the human-review items above.
